# Gateway models

A snapshot of the Vercel AI Gateway's public model list (`GET https://ai-gateway.vercel.sh/v1/models`, no key needed). Calls use the key in the variable the gateway entry's `keyEnv` names (`AI_GATEWAY_API_KEY` by default); a relay is the entry's `baseURL`. The list changes often; rerun the query before changing a default route. Prices are as the list reported them; Assetgrove records each call's actual cost when the gateway reports one.

The snapshot lists 498 models: 320 language, 39 image, 37 video, 28 embedding, 24 speech, 16 transcription, 15 evaluation, 10 realtime and 9 reranking.

## Default routes

Set in `src/routes.ts`. Each is the default route of the adapter that serves it: the gateway's for the 2D operations, Tripo's for the 3D ones. The developer settings override any of them by role or by operation ([docs/settings.md](settings.md#roles-and-routes)); an override that changes the provider or the model carries only the `estimatedCostUsd`, `outputGrant` and `providerTerms` it declares, and must declare the estimate unless its provider is `free`. Each default carries the grant its terms give: every gateway route here is a paid API route that gives ownership, and Tripo on paid credits gives ownership. `compiler` (prompt compilation) and `material-qa` use the `vision` model.

A generated sheet makes one `sheet` call and one `vision` call for the grouping proposal: about $0.32, reserved against the $5 cap before either call. ## Direct routes (Anthropic and OpenAI)

The `anthropic` and `openai` adapters call each provider's own API through the AI SDK's provider packages (`@ai-sdk/anthropic`, `@ai-sdk/openai`, pinned exactly), with the key in `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` (or the entry's `keyEnv`). Their endpoints are fixed: a `baseURL` on either entry exits 2 `settings_invalid`. Both are paid; neither reports usage to an ordinary key, so a call costs its route estimate and the run records `reconcile: "unavailable"`. Typed decisions go through structured output (`decision.decisionSource: "structured-output"`). Each default route carries the grant the provider's API terms give: the customer owns the output (`LicenseRef-anthropic-api` or `LicenseRef-openai-api`, plan `api`, commercial, `relabel: true`). Each model carries its own estimate, a deliberate upper bound per call (the Estimate column); sizes are the gateway default's for the same operation.

Anthropic has no image models, so with Anthropic alone `image` and `edit` have no route and a stage exits 2 `route_unavailable`; pair it with the gateway or OpenAI. The real checks (`pnpm test:real`, test/real/routes.real.ts) call Anthropic vision and decisions and OpenAI planning, decisions, image and edit; an OpenAI key without image access skips image and edit with the provider's reason, and they are then unverified.

## Local-only recipe

Everything 2D except `edit` runs with no network on two loopback OpenAI-compatible servers: an image server (the images API, `/v1/images/generations` and `/v1/images/edits`) and a chat server (`/v1/chat/completions` with image input and JSON-schema `response_format`). Any server that speaks those endpoints works; Assetgrove names none.

1. Start both servers on loopback, for example `http://127.0.0.1:8080/v1` (images) and `http://127.0.0.1:8081/v1` (chat).
2. Add them to the developer settings as `openai-compatible` providers with `"free": true`, which settings allow only on a loopback `baseURL` (a non-loopback host with `free` exits 2 `settings_invalid`). A free provider writes no ledger entry and needs no declared limit.
3. Route `image` to the image server and `vision`, `decisions` and `planning` to the chat server, each with the `outputGrant` and `providerTerms` its model's licence gives; the full settings are in [settings.md](settings.md#roles-and-routes). The openai-compatible adapter has no default routes, so a role left out has no route.
4. Measure the chat model on the prompt policy's red-team set and record its cut in the settings' `promptPolicy.cuts` under `openai-compatible:<model>` ([settings.md](settings.md#roles-and-routes)); without it, a request with prompt text exits 2 `route_unavailable`, since the prompt-policy check does not run on an unmeasured route.
5. `stage` a `still`: every call goes to the loopback servers, decisions through structured output.

A `sprite-strip` needs an `edit` route; with none, it exits 2 `route_unavailable` before any reservation. Route `edit` to a loopback image server that takes reference images, or to a paid provider, to make strips. test/local-route.test.ts proves both against a loopback fixture server.

## 3D routes (Tripo, not the gateway)

3D characters (`character-3d`, [characters-3d.md](characters-3d.md)) call Tripo's API directly with the key in the variable the tripo provider entry's `keyEnv` names (`TRIPO_API_KEY` by default). Their identity call still goes through the gateway. The account is on paid credits, so Tripo's output is owned: the routes' `outputGrant` is `LicenseRef-tripo-paid`, plan `paid`, commercial, `relabel: true`. Each call's cost is the task's reported `consumed_credit` × the `usdPerCredit` of the tripo provider entry in the developer settings ([settings.md](settings.md)); without it, the route estimate.

| Operation | Model                             | What it calls                                                                                        | Estimate per call |
| --------- | --------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------- |
| `model3d` | `tripo/v2.5-20250123`             | `multiview_to_model` with texture and PBR (`image_to_model` when there is only one view): 30 credits | $0.50             |
| `rig3d`   | `tripo/animate-rig-v2.0-20250506` | `animate_rig` with `rig_type` from the gait: 25 credits. The v1 rigger refuses quadrupeds.           | $0.30             |
| `clips3d` | `tripo/animate-retarget`          | `animate_retarget` with one library clip the spec needs, one call per clip                           | $0.20             |

One candidate is one `model3d`, one `model3d-facing`, one `rig3d`, one `clips3d` per library clip the spec needs (a family that is not exactly a library key counts too, since a `clip-map` decision may map it; none when the gait's library is empty) and one `identity` call. The `clip-map` decisions ($0.001 each) are reserved once per request, per non-exact family. With one exact clip that is $1.002 reserved per candidate, or $4.008 for 4 candidates against the $5 cap; each further clip adds $0.20 per candidate.

The `clips3d` route's `library` maps gait → family → `{ clip, loop }`. Tripo's library:

- biped: `preset:idle`, `preset:walk`, `preset:run`, `preset:jump`, `preset:turn`, `preset:hurt`, `preset:fall`, `preset:climb`, `preset:dive`, `preset:slash` and `preset:shoot`;
- quadruped: only `preset:quadruped:walk`. Tripo refuses `preset:quadruped:idle`, `:run`, `:trot`, `:stand`, `:jump` and others as invalid animation names.

So a quadruped `idle` is reported missing, not faked. When the provider adds clips, the library in `src/routes.ts` gains them.

Each route records its provider terms in provenance. The values name the provider's current terms; check and update them when a route changes.
